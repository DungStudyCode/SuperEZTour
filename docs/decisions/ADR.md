# Architecture Decision Records (ADR) — Super EZ Tour

| ID | Status | Decision | Rationale & Consequences |
|---|---|---|---|
| **ADR-001** | **ACCEPTED** | **Native npm Workspaces Enterprise Monorepo (`apps/*`, `packages/*`)** | Unifies `@superez/web`, `@superez/api`, and `@superez/contracts` under one authoritative root `package-lock.json` on Node.js 24 LTS without adding Turborepo/Nx/pnpm complexity. |
| **ADR-002** | **ACCEPTED** | **Node.js 24 LTS + Fastify 5 + Strict TypeScript Modular Monolith (`@superez/api`)** | Native JSON Schema route validation, low memory overhead, clean `buildApp` injection testing, and single-service operational simplicity. |
| **ADR-003** | **ACCEPTED** | **PostgreSQL 17 via `pg` + Supabase Managed PostgreSQL for Production** | Native ACID transactions across 6 lead intake tables, strong `CHECK`/`UNIQUE` constraints, advisory locks, and zero ORM magic. Fastify retains 100% business & auth authority (Supabase Auth and PostgREST Data API are not used). |
| **ADR-004** | **ACCEPTED** | **Explicit Checksummed SQL Migrations & Separate DB Roles** | Migrations run via explicit CLI (`MIGRATION_DATABASE_URL`), serialized by `pg_advisory_xact_lock` and verified by LF-normalized SHA-256 checksums. Server startup never runs DDL; runtime `DATABASE_URL` uses least-privilege DML/SELECT grants. |
| **ADR-005** | **ACCEPTED** | **Shared Versioned Consultation Contracts (`@superez/contracts`)** | `packages/contracts/consultation/v1` is the single source of truth for request/receipt/error JSON Schemas, canonical destination/attraction/culinary/source IDs, and pure Korean phone & `Asia/Seoul` date normalizers. |
| **ADR-006** | **ACCEPTED** | **Atomic Six-Record Intake, Opaque Receipt & Keyed HMAC Idempotency** | `POST /api/v1/leads` commits `leads`, `lead_private`, `consent_receipts`, `lead_idempotency`, `lead_activity`, and `notification_outbox` in one transaction, returning only `SEZ-<32 hex>` + UTC timestamp. Retries with identical `Idempotency-Key` and HMAC-SHA-256 canonical digest replay `200 OK`; modified payloads return `409 IDEMPOTENCY_CONFLICT`. |
| **ADR-007** | **ACCEPTED** | **PostgreSQL Transactional Outbox (No Redis in V1)** | Decouples lead acknowledgement from downstream staff notification delivery without introducing an external message broker at current scale. |
| **ADR-008** | **ACCEPTED** | **Closed Production Intake Gate & Strict ViVu Co-Host Isolation** | Production intake (`LEAD_INTAKE_ENABLED`) and OpenAPI (`/docs`) fail closed until privacy policy, staff workflow, and infrastructure capacity are approved. Live VPS ViVu services (`vivu-backend`, MongoDB, `vivu.conf`, SSH `24700`) remain strictly isolated. |
| **ADR-009** | **ACCEPTED** | **Route & Heavy-Engine Code Splitting in `@superez/web`** | Homepage (`/`), Destination coordinator, Hanoi experience, Da Nang experience, Three.js `FlyThroughScene`, `maplibre-gl`, and `QuickConsultationForm` load as separate async chunks to minimize initial customer download size while preserving 60fps GSAP/Lenis/WebGL lifecycles. |
| **ADR-010** | **PROPOSED** | **Separate Admin Build (`apps/admin`) + Server Sessions & RBAC (Task 03.3)** | Dedicated backoffice SPA served under `/admin/` with `HttpOnly`/`Secure` server sessions (preferring workforce OIDC + MFA), masked PII lists, and audited contact reveal. Deferred until Task 03.3 approval. |
| **ADR-011** | **PROPOSED** | **Production Supabase Region, Retention TTL, Backup RPO/RTO & Notification Provider** | Requires Project Owner & legal sign-off on cross-border Korean PII disclosures, retention/anonymization schedule, off-host encrypted backup cadence, and verified staff notification channel (Email/Telegram). |
